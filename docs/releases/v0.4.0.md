# PineForge v0.4.0 - A Face That Means It

> [!CAUTION]
> Flashing may leave a sealed PineTime unusable or require recovery. A sealed watch has no exposed SWD pads, so an image that neither boots nor reaches the bootloader's recovery path can only be waited out until the battery runs flat. Keep an official InfiniTime DFU package available and read the installation and recovery instructions before flashing.

[v0.3.0](v0.3.0.md) built the shell and the first applications standing in it. This release is about how the thing looks and how fast it draws - and about a measurement habit, because most of what follows started as a guess that turned out to be wrong.

Settings and BLE bonds survive the update: settings migrate from every earlier format, and the bond layout did not change, so there is no re-pairing.

## The FORGE face finished

The clock's numerals were always built from rectangles rather than from a font - seven strokes and a table of which are lit, with the unlit ones drawn too, which is what makes a number read as an instrument rather than as a square typeface. The readings underneath were not. They were a line of small type: `72% BAT 63 BPM 8214 ST`, three unrelated numbers in a row with the colour changing partway along for a reason nobody could see.

They are segments now, at a quarter of the clock's size. The face carries no font at all.

That took three wrong turns to reach, all of which rearranged the footer while leaving it set in type: a two-column grid, then three progress bars, then one. Each was tidier than the last and none of them belonged, because the mismatch was never the arrangement - it was that one half of the face was an antialiased glyph atlas and the other half was rectangles.

The charge keeps three places whether or not it needs them, and the unused ones stand unlit rather than closing up. Before the first battery reading every place is unlit, which says "nothing measured" the way an instrument does rather than by showing a zero.

Steps and pulse left the face. Both now have applications with room to show more than a footer ever could, and the pulse only ever appeared once a measurement had returned, so its line came and went underneath the others.

## A steps application

The day's count, in the same numerals the clock is built from, over a gauge divided into five cells against a ten-thousand goal.

Five cells rather than one continuous bar, because a bar answers "roughly how far" and cells answer "how many thousands" - which is the question somebody checking their steps is actually asking. It turns green at the goal rather than merely filling up: a full bar and an almost-full one are a few pixels apart, and the difference between them is the point of having a goal.

The leading place stays as an unlit digit rather than going blank or showing a zero. Blank reads as a fault, a zero says the count begins with one, and both let the number shift under the eye as it gains a place.

## Notifications on a card

A message now sits on a raised surface with rounded corners - the same shape a launcher tile and a menu row already have. The gesture that clears a message is a swipe, and a swipe reads as moving something; text on the background has nothing to move.

An empty inbox is the same card with different words. It used to be a bare line of text while a message got a card, so one screen had two layouts and the jump between them was the most conspicuous thing about arriving there.

The body text has a size of its own. The firmware had a UI size and a label size and neither is a reading size: a notification body set in the label face fitted 203 characters into a card that never carries more than a hundred, and in the UI face it would not have fitted at all. A third atlas sits between them, at a cost of 6,840 bytes of flash.

## Drawing, measured rather than assumed

The rendering work in this release began as a comparison with InfiniTime and produced four corrections to my own predictions. They are worth naming, because the pattern is more useful than any one of the fixes.

**Waking no longer repaints.** Sleeping the ST7789 stops its scan, not its memory, so the panel still holds the picture it went dark with; waking owes only what moved. This is the single largest saving in the release, and it is what InfiniTime has always done. Making it correct also meant fixing a real defect: the watchface's record of what had changed was overwritten by each event rather than accumulating, so a naive version of this change would have silently dropped every reading taken while the panel was dark.

**A line of text is one address window, not one per character.** A glyph used to be its own rectangle, and a display driver turns every rectangle into an address window plus a memory write - roughly 900 SPI transactions for a face that a few dozen would carry.

**Composing a screen was the bottleneck, not the bus.** A measured transition spent 614 ms rasterising against 176 ms sending. That inverted the plan: overlapping DMA with rasterising, which had looked like the big win, could only ever have recovered the smaller number, and it was dropped.

**The wire is slower than its clock, and not for the reason I thought.** Twice I predicted a per-call cost and twice it was a per-pixel one. Enlarging the display buffer to cut SPI write calls by a factor of four bought 5 ms of 176; it is kept for what it does to the direct paint path, not for that number.

Screens are also opaque by construction now rather than by clearing first. The notification screen was the last one that blanked the panel before drawing it, which cost a full-panel transfer before anything appeared and filled every stripe of a transition twice.

## Under the surface

The clock's numerals moved into a module of their own, sized by the caller, which is what let the steps application be set in them. The panel's dimensions had three definitions and now have one. The daily step goal was about to have two - the application and the watchface both divide against it - and now lives with the rest of the product policy.

The screen previews under `tools/uipreview` routed every event to the watchface, so the pulse and steps sheets rendered their empty state. They now route readings the way the display task does.

## Known limits

The diagnostics screen's paint timings are knowingly broken: standing on that screen overwrites them with its own idle ticks. It is not being fixed, because proper SWD debugging is arriving and on-panel instrumentation stops being the only way to read a timing.

This release has still only been worn on one watch. See [tested configurations](../TESTED-CONFIGURATIONS.md) for what that does and does not establish.

## Reproducing this build

The published image is built from the commit this release is tagged on. That is a change from v0.3.0, where the tag necessarily sat one commit later because it pointed at the commit recording the checksums.

The checksums are published in the release body instead of in the repository, which removes the problem: nothing in the tagged tree has to know a hash that cannot exist until the build does. Check the archive against the asset published with this release, and the image against what a rebuild of the tagged commit reproduces.

The firmware embeds the commit it was built from so a watch can say what it is running, which means the identifier is part of the image: building the same source at a different commit produces different bytes. With the tag checked out the image is byte-reproducible; the archive around it is not, because `adafruit-nrfutil` records file timestamps, so every packaging run produces a different archive hash.

`rust-version` now names the toolchain this project is actually built and tested with rather than a lower bound nothing checks. The internal crates are versioned in lockstep with the firmware for the same reason - they are not published, and two unrelated numbers were only ever going to be compared.
