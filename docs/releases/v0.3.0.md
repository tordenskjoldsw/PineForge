# PineForge v0.3.0 - The Navigation Shell, and Something to Put on It

> [!CAUTION]
> Flashing may leave a sealed PineTime unusable or require recovery. A sealed
> watch has no exposed SWD pads, so an image that neither boots nor reaches the
> bootloader's recovery path can only be waited out until the battery runs flat.
> Keep an official InfiniTime DFU package available and read the installation
> and recovery instructions before flashing.

[v0.2.0](v0.2.0.md) built a platform and admitted it had nowhere to go: settings
and firmware hung off provisional gestures, waiting for a shell that did not
exist. This release is that shell, and the first applications standing on it.

It is also the release where PineForge stopped being something to test and
became something to wear. It has run on my own watch since late July 2026.

Settings and BLE bonds survive the update: settings migrate from every earlier
format, and the bond layout did not change, so there is no re-pairing.

## A place for applications to live

Swiping up from the watchface opens a **launcher** - four icon tiles to a page,
paging horizontally because the vertical axis is spent getting there. Settings,
firmware, about, a **flashlight** that makes the panel itself the light, and a
**pulse** app that takes a heart-rate reading on demand.

The provisional routes are gone. Swipe down is now **notifications**, one
message filling the screen rather than a list of subject lines: 240 pixels fit
about six lines of body text, so a list would show almost nothing of any message
and still cost a second screen to read one. Down browses, right dismisses, up
leaves. Dismissing sits on the other axis from browsing on purpose - both are
single swipes and one of them destroys something.

The notification tally left the watchface in the same change. A count there
would only have been a second place to keep the same fact right.

Left is unassigned. It was reserved for a quick settings panel, which was
dropped rather than built: never specified beyond the reserved gesture, and the
launcher had meanwhile taken its shape, one swipe from the face and already
carrying the torch and the settings gear.

## Settings that are a tree, not a screen

Settings split into a root of entries and a leaf per setting, each leaf offering
that setting's presets. Brightness, dim timeout, display-off timeout,
heart-rate interval, wake gesture, watchface.

Two of those are new. **Heart rate** can now be measured on a background
interval, using InfiniTime's presets, as well as on demand. **Wake gestures**
are selectable rather than fixed.

All six persist. The stored format went from 3 to 5 and every version back to
the first still migrates on decode, with a test per version.

## The watch says what it is

An **about** screen names the running build by release, commit and date, and the
same string goes out over BLE. The status corner marks an image that is still
unconfirmed. Between them, a watch that has been flashed several times can be
asked which firmware it is actually running - which, before this, it could not.

## Looks

The interface is set in antialiased JetBrains Mono. Menu rows became rounded
buttons, four to a page, and a row can say what choosing it means. Every screen
but the watchface carries a status corner; every paginated screen carries a page
rail. The accent is verdigris and the healthy-battery green is deeper.

Screens are now rendered on the host as well as the watch: `tools/uipreview`
draws every screen, including the system modals and the states an update can be
refused in, into image files. Reviewing a layout no longer costs a DFU transfer.

## Fixes worth naming

**A tap no longer costs a full page of SPI.** Pressing a launcher tile
repainted all four, and pressing a menu row repainted the page. Nothing here
buffers pixels, so a repaint is a transfer of exactly the area it names: at
8 MHz a tile is about 18 ms and the page about 74 ms, paid twice per tap. The
list model knew which slot the press belonged to and threw it away; it now says,
and only that slot is painted.

**The charger is noticed on either pin.** Whether the watch is charging and
whether it is on the pad are two different signals, and only one was watched.

**A stack overflow now faults** instead of quietly overwriting a suspended
task's state, and a dead panel no longer takes the boot with it.

**A stalled DFU transfer recovers without a reconnect.** Diagonal swipes are
accepted, a touch whose lift was never reported is forgotten, and the gesture
after a wake is no longer swallowed.

## Known limitations

- **Step counts and heart-rate readings have never been compared against a
  reference.** Both produce numbers, and a wrong number is believed in a way a
  missing feature is not. Treat them as indications.
- Battery life has not been measured, in any state.
- Everything here rests on one watch, one bootloader version and one phone. See
  [`../TESTED-CONFIGURATIONS.md`](../TESTED-CONFIGURATIONS.md).
- OTA transfer speed is bounded by the BLE link layer, not by flash, and is
  slower than stock InfiniTime.
- Only one production watchface, and it is a bring-up aesthetic rather than a
  chosen one.

## Memory

|---|---:|---:|---:|
| Flash | 354,732 B | 374,824 B | 420 KiB |
| Static RAM | 43,412 B | 44,916 B | 44 KiB |
| Free for stack growth | 22,116 B | 20,612 B | 20 KiB minimum |

Static RAM sits 140 bytes under its budget. That is thin enough to be worth
saying out loud: the next screen will have to pay for itself.

## Installation

1. Fully charge the watch.
2. Save a known-good official InfiniTime DFU ZIP on the phone.
3. Read `GETTING-STARTED.md` and the sealed-device testing guide.
4. Download `pineforge-mcuboot-app-dfu-0.3.0.zip` from this release.
5. Verify its SHA-256 checksum against the value below.
6. Open the ZIP with Gadgetbridge's firmware installer.
7. Keep the phone and watch close together until validation and reboot finish.

Do not extract the DFU ZIP before giving it to Gadgetbridge.

## Recovery

- Before PineForge is confirmed, a restart lets MCUBoot roll back to the
  previous image - reachable from the firmware screen or by holding the side
  button for two seconds.
- To start the bootloader's minimal InfiniTime recovery image, hold the physical
  side button during boot until the boot logo turns red.
- Connect to that recovery image over Bluetooth and install a known-good
  InfiniTime or PineForge DFU ZIP.

## Verification

The release asset contains `manifest.json`, `pineforge-image.dat` and
`pineforge-image.bin`.

The MCUBoot image is byte-reproducible: rebuilding this commit yields the same
`pineforge-image.bin`. The archive around it is not, because `adafruit-nrfutil`
records file timestamps in the ZIP, so every packaging run produces a different
archive hash. Check the archive against the asset published with this release,
and the image against the value a rebuild reproduces.

Build tooling is pinned from this release on: `scripts/setup-build-tools.sh`
installs MCUBoot at a verified commit and the Python tooling at fixed versions,
so the image is reproducible on a machine that was set up later.

SHA-256:

```text
ac1121f894aa6d9877abd183971d6c0ab42b41ef97512b9c68dac207ce43af44  pineforge-mcuboot-app-dfu-0.3.0.zip
b48b7c2840d1e790fbc575f35967dcf7cdb647dcd03fa6286c2e84fc603fd927  pineforge-image.bin
```

The image hash above was checked by rebuilding after `cargo clean`, not merely
asserted: both builds produced the same bytes.
