# PineForge v1.0.1 - The Watch Explains Its Own Version

[v1.0.0](v1.0.0.md) split the number PineForge calls itself from the number it reports over Bluetooth, and said plainly that Gadgetbridge would go on showing `1.14.0` for a watch running `1.0.0`. That was the right call and it left one thing undone: the watch had no way to say so. Someone holding a phone that disagrees with a screen had to find the release notes to learn that both were correct, which is the one place nobody looks while staring at the disagreement.

The About screen's build page now carries a fifth row.

```
BUILD    1.0.1
COMMIT   <the commit this image was built from>
DATE     <build date>
BOOT     MCUBOOT
BLE      1.14.0
```

`BLE` is the firmware revision the Device Information Service serves, and it comes from `COMPANION_PROTOCOL_VERSION` in `build.rs` - the same constant the characteristic itself is built from, so the row cannot drift from what a phone is actually told. A row that named the wrong number would be worse than no row at all.

Nothing else changed. There is no behavioural difference between this image and `1.0.0` beyond the added row, no settings migration, and no reason to re-pair.

## If you are coming from a 1.14.0 package

The images packaged `1.14.0` and `1.14.0+1` predate the version split, so on those the About screen showed `1.14.0+1` - correct at the time, because the release really was numbered after the protocol then. This is the first image on which the build page shows the PineForge release rather than the protocol generation, which is worth knowing before reading it as a version having gone backwards.

Gadgetbridge will still show `1.14.0` after this update, and that remains deliberate.

## What it costs

Eight bytes of static RAM, one `&'static str`. Production holds 196 bytes against its ceiling and the diagnostics build 12, both inside the stack reserve a BLE key exchange needs.

Twelve bytes is thin enough to state rather than bury: the next static added to the diagnostics build is the one that will not fit. The shipping image is not at that point, but instrumentation is, and `docs/ARCHITECTURE.md` explains why the ceiling is a measurement rather than a preference.

## Not established

The row itself is not in question: this release was flashed as the `1.0.0+1` package and the build page shows it on the watch. That flash also settled the one thing `v1.0.0` had left over, since it is the first image on which About names the PineForge release rather than the package the protocol was numbered after.

Everything else `1.0.0` left open remains open - the forecast row with real data, the step counter across a midnight, the background heart-rate interval reaching a phone, and weather arriving without the debug menu. `docs/TESTED-CONFIGURATIONS.md` is the record of which paths have actually been run.

## Installing

`GETTING-STARTED.md` covers flashing, what an unconfirmed image is, and how to get back to InfiniTime. Worth reading first on a sealed watch, which has no exposed SWD pads and therefore no way in except the bootloader's own recovery path.
