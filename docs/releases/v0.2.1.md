# PineForge v0.2.1 — Gesture and Memory Fixes

> [!CAUTION]
> This is experimental firmware, not a production release. It may require rollback or recovery and could leave a sealed PineTime unusable. Keep an official InfiniTime DFU package available and read the installation and recovery instructions before flashing.

A patch release on [v0.2.0](v0.2.0.md), with one user-visible fix and one budget closed. Settings, watchface choice and BLE bonds are all preserved across the update: no persisted record format changed.

## A gesture no longer activates the control under the finger

A button activates on release inside its bounds, and the input task published the touch before the swipe. The minimum swipe distance is 40 pixels while a menu row is 200 wide, so a swipe that began and ended on the same row did both things: it activated the row and then navigated.

On the firmware screen that meant **swiping back out with the finger resting on the `RESTART` row restarted the watch**, and on the settings screen a horizontal swipe cycled whichever setting was under the finger. Both were present in v0.2.0.

The rule that fixes it already existed for system modals — whoever interprets an input consumes it — and now covers gestures too. Once a gesture claims the touch, the press in flight is abandoned rather than activated, and the remaining reports of that finger stay off the screen until it lifts. To a button this is indistinguishable from the finger being dragged out of it.

One consequence worth knowing: a sloppy tap that the touch controller itself reports as a slide no longer activates anything. Previously it activated *and* navigated, which is not a better answer.

## Static RAM now meets its design target

The display transition scratch went from a 16-pixel stripe to 12, which divides the 240-pixel span evenly into 20 stripes. The screen is composed once per stripe, so this is a direct trade of render time for RAM — it is the only large allocation whose size does not rest on a validated protocol floor.

| Resource | v0.2.0 | v0.2.1 | Target |
|---|---:|---:|---:|
| Static RAM | 45,332 B | 43,412 B | 44 KiB |
| Free for stack growth | 20,196 B | 22,116 B | 20 KiB minimum |
| Transition scratch | 7.5 KiB | 5.6 KiB | 8 KiB maximum |
| Flash | 354,180 B | 354,732 B | 360 KiB |

CI now enforces these design targets rather than the hard slot limits, because a target nothing checks is how the overshoot appeared in the first place. `docs/ARCHITECTURE.md` records the four largest static allocations and the command that measures them.

## Still to come

The application launcher and quick-settings screens remain outstanding, so the gesture map is recorded but only partly routed: swipe down opens display settings and swipe right the firmware screen, both provisionally, until the launcher exists. Notifications are received and counted on the watchface but have no screen of their own.

## Known limitations

- OTA transfer speed is slower than stock InfiniTime and is bounded by the BLE link layer rather than by flash.
- PineForge remains incomplete and is intended for development and hardware testing.
- The release has not been validated across all PineTime hardware or bootloader revisions.
- Recovery from a failed update may be difficult on a sealed watch.

## Installation

1. Fully charge the watch.
2. Save a known-good official InfiniTime DFU ZIP on the phone.
3. Read `GETTING-STARTED.md` and the sealed-device testing guide.
4. Download `pineforge-mcuboot-app-dfu-0.2.1.zip` from this release.
5. Verify its SHA-256 checksum against the value below.
6. Open the ZIP with Gadgetbridge's firmware installer.
7. Keep the phone and watch close together until validation and reboot finish.

Do not extract the DFU ZIP before giving it to Gadgetbridge.

## Recovery

- Before PineForge is confirmed, a restart lets MCUBoot roll back to the previous image — reachable from the firmware screen or by holding the side button for two seconds.
- To start the bootloader's minimal InfiniTime recovery image, hold the physical side button during boot until the boot logo turns red.
- Connect to that recovery image over Bluetooth and install a known-good InfiniTime or PineForge DFU ZIP.

## Verification

The release asset contains `manifest.json`, `pineforge-image.dat` and `pineforge-image.bin`.

The `MCUBoot` image is byte-reproducible: rebuilding this commit yields the same `pineforge-image.bin`. The archive around it is not, because `adafruit-nrfutil` records file timestamps in the ZIP, so every packaging run produces a different archive hash. Check the archive against the asset published with this release, and the image against the value a rebuild reproduces.
